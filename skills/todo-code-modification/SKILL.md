# 待辦事項程式碼或頁面修改 Skill

## 目的

當使用者要求修改待辦事項相關的程式碼、功能或頁面時，協助安全地分析、實作、驗證並說明變更。

## 執行流程

1. 先閱讀 `AGENTS.md` 及相關專案說明文件。
2. 檢查專案的語言、框架、目錄結構、套件管理方式與現有測試或 lint 設定。
3. 找出待辦事項的資料模型、狀態管理、API、元件、頁面與樣式；不要重複建立既有功能。
4. 先釐清使用者要修改的範圍。若需求足夠明確，直接實作；若會造成資料遺失、破壞既有行為或有多個互斥方案，再請使用者確認。
5. 遵循專案既有命名、格式、架構與相依套件；除非必要，不要引入新的框架或大型套件。
6. 修改時維持待辦事項的基本能力：新增、列出、完成／恢復未完成與刪除。
7. 處理基本邊界情況：空白內容、不存在的項目、重複完成、重複刪除、空清單與無效輸入。
8. 若修改頁面，確保具備響應式設計、鍵盤操作、清楚的 focus 狀態、可理解的按鈕文字與足夠色彩對比。
9. 若修改資料格式或 API，維持向後相容；必要時提供遷移或預設值處理。
10. 新增或更新相容的測試。至少驗證成功流程與主要邊界情況。
11. 執行專案提供的 formatter、lint、測試與 build/check 指令；若沒有相應指令，明確說明未執行的項目。
12. 完成後回覆：修改摘要、變更檔案、驗證結果、可能的限制與使用方式。

## 實作原則

- 不要捏造專案中不存在的檔案、指令、API 或測試結果。
- 不要只修改畫面而忽略資料持久化或狀態同步。
- 不要刪除既有待辦資料，除非使用者明確要求且已處理確認流程。
- 若使用者只要求修改頁面，仍要確認畫面操作與實際資料狀態一致。
- 若使用者只提供模糊需求，先用現有程式碼推斷最小可行修改，並在回覆中說明假設。

## 回覆格式

完成後使用以下結構回覆：

1. **已完成**：一句話說明結果。
2. **修改內容**：列出主要檔案與功能變更。
3. **驗證結果**：列出實際執行的指令與結果；未執行的項目要明確標示。
4. **使用方式**：若有新增操作，提供簡短範例。
5. **注意事項**：列出相容性、限制或仍需人工確認的事項。
