# 網頁文章轉 JSON Skill

## 目的

當使用者提供一篇網頁文章的網址、網頁內容或兩者皆有時，將文章資訊整理成一個 JSON 檔案。

## 執行規則

1. 先取得並閱讀使用者提供的網頁文章；若只有網址，使用可取得的頁面內容；若只有文章內容，直接從內容整理資訊。
2. 擷取以下欄位：
   - `url`：文章網址。若無法取得，使用 `null`。
   - `title`：文章標題。優先使用頁面正式標題，無法確認時使用 `null`。
   - `author`：作者。若頁面未提供或無法確認，使用 `null`，不可猜測。
   - `published_at`：發佈時間。使用 ISO 8601 格式；若只有日期，保留日期格式（例如 `2026-10-12`）；無法確認時使用 `null`。
   - `summary`：以繁體中文撰寫的客觀摘要，通常為 2–5 句，涵蓋文章主旨、重要觀點與結論；不可加入原文沒有支持的資訊。
3. 保留原始網址，不要自行改寫或縮短網址。
4. 若欄位資料有多個可能值，選擇頁面明確標示的值；仍無法判定時使用 `null`，並在回覆中說明。
5. 產生合法且 UTF-8 編碼的 JSON，使用 2 個空白縮排，不要在 JSON 內加入註解或 Markdown 標記。
6. 預設將檔案寫入 `articles/<slug>.json`：
   - `<slug>` 使用標題的小寫英數字與連字號。
   - 若標題為中文或無法產生穩定 slug，使用 `article-YYYY-MM-DD-HHmmss.json`。
   - 若使用者指定檔名，遵循使用者指定的檔名。
7. 若使用者提供的內容不足以可靠擷取某欄位，使用 `null`，不要捏造資料。
8. 完成後回覆產生的檔案路徑，並簡短列出無法確認的欄位。

## JSON 結構

```json
{
  "url": "https://example.com/article",
  "title": "文章標題",
  "author": "作者姓名",
  "published_at": "2026-10-12T09:30:00+08:00",
  "summary": "文章摘要。"
}
```

## 輸入不足時

- 使用者沒有提供網址、文章內容或可識別的文章來源時，先請使用者提供文章網址或貼上文章內容。
- 網頁需要登入、無法存取或內容不完整時，使用現有資訊產生結果，將無法確認的欄位設為 `null`，並清楚說明限制。
- 不要輸出與指定結構不同的額外欄位，除非使用者明確要求。
